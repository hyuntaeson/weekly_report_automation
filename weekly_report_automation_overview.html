프로젝트 목적

왜 이 프로그램을 만들었는가

매주 1회 주간회의를 위해, 지난 한 주 동안 내가 수행한 작업 내용을 수작업 취합 없이 자동으로 수집·집계·요약해 보고서로 생성하는 것이 목적입니다.

해결하려는 문제

  • 업무 활동이 파일시스템·Outlook·Teams·브라우저·IDE 등 여러 도구에 분산되어 있어 수작업 취합이 어려움
  • 주간 단위로 "무엇을 했는지" 기억에 의존 → 누락·왜곡 발생
  • 매주 반복되는 보고서 작성에 소요되는 시간 절감 필요

목표

  • 활동 데이터의 자동 수집 — PC 사용 중 백그라운드에서 무개입 수집
  • 수집 데이터의 정규화·저장 — SQLite에 소스/액션/시각 단위로 통합
  • AI 요약이 포함된 보고서 — Markdown·Word 2종 산출
  • 다른 사용자도 사용 가능 — 개인 자격증명만 교체하면 되는 배포 구조
  • OS 제한 없이 제공 — Windows·macOS 어디서든 동작, 플랫폼별 기능 차이는 자동 폴백으로 흡수

왜 웹이 아닌 로컬 프로그램인가

수집 대상이 전부 내 PC 안에 있기 때문에, 로컬에서 실행되는 프로그램 형태가 필수입니다.

  • 로컬 파일 실시간 감시 — Documents/Downloads 등 폴더를 백그라운드에서 감시하는 것은 웹 앱이 접근할 수 없는 영역
  • 프로세스 감지 — "지금 VS Code·Teams가 실행 중인가"를 확인해 작업 세션을 기록하는 것도 로컬에서만 가능
  • 로컬 토큰 보관 — 회사 인증 토큰을 외부 서버에 올리지 않고 본인 PC에만 저장
  • 사내 보안 정책 — 업무 파일 경로·메일·채팅 기록이 회사 밖 서버로 나가지 않아 데이터 유출 우려 없음

수집 → 저장 → 생성의 4계층 파이프라인

계층 구성

계층역할구성 요소
수집활동 이벤트 캡처파일시스템 감시 · 브라우저 방문 기록 · IDE 활동 · Outlook 메일/캘린더 · Teams 채팅/일정 · Slack·Confluence 활동
통합주기적 수집 오케스트레이션소스별 주기로 백그라운드 자동 수집, 사용자가 수동으로 즉시 수집할 수도 있음
정제노이즈·민감정보 제거임시 파일·중복 이벤트·인증 과정 URL 등 무의미하거나 민감한 데이터를 보고서 전 단계에서 정리
저장활동 정규화·영속화SQLite에 모든 소스의 활동을 통합 저장 — 중복 방지, 주간 집계, 활동의 의미 벡터까지 함께 축적
생성집계·요약·산출주간 데이터를 집계·요약해 Markdown과 Word 두 가지 보고서로 출력
AI 분석수집 데이터의 의미 분석·그룹화임베딩 클러스터링으로 주제별 자동 분류 · 소스별 맞춤 요약 체인 · 주간 활동 요약
실행사용자 인터페이스데스크톱 GUI — 추적 시작/중지, 수집 실행, 앱별 작업 현황 실시간 표시, 감시 폴더 관리

데이터 흐름

활동 발생 → 수집기가 이벤트 정규화 → SQLite 적재(중복 제거) → 주간 보고 시 노이즈 필터·중복 제거 후 집계 → AI 분석(주제 분류·요약) → Markdown/Word 출력

AI 적용 계층

  • 주제별 자동 분류 — 임베딩 클러스터링으로 흩어진 활동을 "의미"로 묶어, 보고서를 단순 나열이 아닌 주제(작업) 단위로 재구성
  • 임베딩 영속 저장 — 활동 벡터를 누적 저장해 재계산 없이 재사용, "지난주 유사 작업" 검색의 기반이 됨
  • 요약 체인 표준화 — 소스별 프롬프트를 체인으로 관리해 요약 품질을 일원화
  • 파이프라인 구조화 — 수집→필터→분석→집계→출력을 단계별 그래프로 구성해 조건 분기·폴백·단계별 확장 용이

사내 DevX MCP
(sm-ops-pub-mcp)		Teams/메일 조회 도구 분석 → 동일한 위임권한 인증 방식을 Python으로 재구현사내 표준 인증 체계 재활용, Azure 앱 등록 불필요
사내 LiteLLM 프록시
(haiku-4-5 · text-embedding-3-large)		Chat Completions로 소스별 텍스트 요약(Teams/메일/문서) + 임베딩 엔드포인트로 활동 벡터화 → 의미 클러스터링보고서를 단순 로그 나열이 아닌 의미 단위 요약으로. 외부 API 키 없이 사내 프록시만으로 요약·임베딩 모두 해결
Microsoft first-party 인증
(디바이스 로그인)		Microsoft Office 같은 자사 앱의 공용 인증 경로를 이용해, Azure에 별도 앱 등록·관리자 승인 없이 개인 로그인 1회만으로 Teams/일정 데이터 접근. 토큰은 자동 갱신보안 정책상 막혀있던 앱 등록 절차를 우회, 누구든 본인 계정 로그인만으로 즉시 사용 가능
AI 코딩 에이전트
(Claude Code/Devin)		프로젝트 설계·구현·테스트·문서화 전 과정을 에이전트 협업으로 개발개발 속도 향상, 테스트·결정기록 자동 축적
자체 MCP 개발Slack 대화 조회 MCP를 devx-mcp.yaml 규격으로 제작, 사내 마켓플레이스 배포사내 다른 사용자/에이전트가 재사용 가능한 자산화

교육 기술의 실전 적용

기술적용 방법기대 효과
임베딩 + VectorDB
(text-embedding-3-large)		 활동(채팅·파일·메일·방문)을 벡터로 변환해 SQLite 벡터 테이블에 축적(재계산 없이 재사용) → 코사인 유사도로 비슷한 의미의 활동끼리 자동 분류 + LLM이 주제명 생성 파일·채팅·브라우저에 흩어진 동일 작업이 "주제별"로 묶여 보고서 가독성 향상 · 주간 축적으로 "지난주 유사 작업" 검색
RAG
(의미 검색+요약)		 주간보고서 생성 단계에서 적용 — DB 활동 조회 → 노이즈 필터 → [RAG 검색] 의미 기준으로 관련 활동만 추출 → [LLM] 그 활동들만 요약 → 보고서 섹션에 삽입. 미리 정의한 질의("장애 대응", "교육·회의", "문서 작업" 등)로 섹션별 내용이 자동 생성됨 키워드가 아닌 의미 기준으로 관련 활동 추출 — "장애"라는 단어가 없어도 서버 이슈 채팅·패치 파일·장애회의가 잡힘. 나열형 보고서 → 목적 단위로 분류된 요약 보고서
LangChain / LCEL
(요약 체인 표준화)		 LLM 호출을 프롬프트 → 모델 → 파서 체인으로 표준화. 모델 교체는 설정값만 변경, 소스별(파일/메일/채팅) 프롬프트 템플릿 분리, 재시도·폴백 로직 체인 내장 모델·프롬프트 변경이 코드 수정 없이 가능, 요약 품질 일원화
LangGraph
(파이프라인 구조화)		 수집→노이즈 필터→소스별 요약→병합→출력을 노드/엣지 그래프로 구성. LLM 실패 시 폴백 분기를 그래프 엣지로 표현 단계별 오류 대응이 명확하고, 향후 새 수집 소스·요약 단계 추가 시 노드만 붙이면 되는 확장 가능한 구조
외부 인프라 추가 없이 사내 MCP·LLM 프록시(임베딩 포함)·표준 OAuth만으로 개인 수준의 AI 활용 파이프라인을 구축하는 것이 이 프로젝트의 핵심 접근법입니다.
